     1→# LAN File Share + Chat App — Worklog
     2→
     3→## Project Overview
     4→A multi-device, real-time LAN file-sharing + messaging web app built on Next.js 16 (App Router). One host serves the app; every device on the same network joins via browser. Real-time layer is a Socket.io mini-service; persistence is SQLite via Prisma.
     5→
     6→> Note: The original prompt specified Node/Express + a separate React client. We adapt to this environment's stack: **Next.js 16 + App Router** for frontend + API routes, plus a **Socket.io mini-service** (`mini-services/realtime/`) on port **3003** for real-time fan-out. Prisma + SQLite handles persistence.
     7→
     8→## Architecture
     9→```
    10→Browser (each device) ──┬── HTTP  ──> Next.js API routes (port 3000) [persistence + file transfer]
    11→                        └── WS    ──> Socket.io mini-service (port 3003) [real-time]
    12→Caddy gateway routes /?XTransformPort=3003 -> localhost:3003
    13→```
    14→- Next.js API = single DB writer (Prisma).
    15→- Socket service = real-time only (in-memory device registry); persists chat messages by POSTing to Next.js API `http://localhost:3000/api/messages`.
    16→
    17→## Data Models (Prisma — see prisma/schema.prisma)
    18→- `Device`: id (client stable cuid), name, deviceType, userAgent, avatarColor, lastSeen
    19→- `Message`: id, senderId, senderName, recipientId (null=group), content, timestamp, read
    20→- `FileRecord`: id, name, originalName, size, mimeType, senderId, recipientIds (csv), isBroadcast, storagePath, status, totalChunks, receivedChunks, expiresAt, downloadCount, createdAt
    21→
    22→## API Contracts (Next.js routes, all relative paths)
    23→- `GET  /api/network-info` -> `{ url, host, port, qrCodeDataUrl }`
    24→- `POST /api/upload/init`  body `{ fileName, fileSize, mimeType, totalChunks, senderId, senderName, recipientIds[], isBroadcast }` -> `{ fileId }`
    25→- `POST /api/upload/chunk` multipart field `chunk` + fields `fileId, chunkIndex` -> `{ fileId, receivedChunks, totalChunks }`
    26→- `POST /api/upload/complete` `{ fileId }` -> `{ file: FileRecord }`
    27→- `GET  /api/files?deviceId=xxx&scope=sent|received|all` -> `{ files }`
    28→- `GET  /api/files/:id` -> FileRecord
    29→- `GET  /api/download/:id` -> streams file (increments downloadCount)
    30→- `DELETE /api/files/:id` -> `{ ok }`
    31→- `POST /api/messages` `{ senderId, senderName, recipientId|null, content }` -> `{ message }`
    32→- `GET  /api/messages?deviceId=xxx&type=group|private&peerId=yyy` -> `{ messages }`
    33→- `POST /api/devices` `{ id, name, deviceType, userAgent, avatarColor }` -> upserts device, returns `{ device }`
    34→- `GET  /api/devices` -> `{ devices }` (DB records; live online status comes from socket)
    35→
    36→## Socket Events (port 3003, path `/`, client connects via `io('/?XTransformPort=3003')`)
    37→Client -> Server:
    38→- `device:join` `{ deviceId, name, deviceType, userAgent, avatarColor }`
    39→- `chat:message` `{ senderId, senderName, recipientId|null, content, timestamp }`
    40→- `chat:typing` `{ senderId, senderName, recipientId|null, isTyping }`
    41→- `chat:read` `{ recipientId|null }` (reader marks conversation read)
    42→- `file:sent` `{ file: FileRecord, senderId, senderName }` (after upload completes)
    43→- `file:downloaded` `{ fileId, downloaderId, downloaderName }`
    44→
    45→Server -> Client:
    46→- `device:list` `{ devices: [{deviceId,name,deviceType,avatarColor,online,socketId}] }`
    47→- `device:joined` `{ device }`
    48→- `device:left` `{ deviceId }`
    49→- `chat:message` (group = broadcast; private = only to sender + recipient)
    50→- `chat:typing`
    51→- `chat:read` `{ readerId, recipientId|null }`
    52→- `file:sent` (to recipients / broadcast)
    53→- `file:downloaded` (to sender)
    54→- `connect` / `disconnect`
    55→
    56→## Device identification
    57→Each browser generates a stable cuid `deviceId` once, stored in `localStorage`. Device type is detected from userAgent (desktop/tablet/mobile). Avatar color is a stable hash-based hue.

   118→2. `api/upload/init/route.ts` — `POST`: validates body, upserts sender Device, sanitizes originalName (strips `/`, `\`, `..`), computes extension, generates `crypto.randomUUID()` stored name, creates FileRecord (`status='uploading'`, `receivedChunks=0`, `storagePath=<cwd>/uploads/<uuid>.<ext>`), pre-creates an empty file at storagePath, returns `{ fileId }`.
   119→3. `api/upload/chunk/route.ts` — `POST` multipart: parses `request.formData()`, reads `fileId`, `chunkIndex`, and the `chunk` File field; writes the bytes to `${storagePath}.part${chunkIndex}` (resumable / out-of-order safe), increments `receivedChunks` via Prisma `{ increment: 1 }`, returns `{ fileId, receivedChunks, totalChunks }`.
   120→4. `api/upload/complete/route.ts` — `POST { fileId }`: opens the final storagePath with `fs.open('w')`, concatenates `.part0..partN-1` in order, deletes parts, stats the final file (warns on size mismatch but does not fail), sets FileRecord `status='ready'`, returns `{ file }`.
   121→5. `api/files/route.ts` — `GET ?deviceId=&scope=all|sent|received`: scope `sent` → `senderId=deviceId`; `received` → `status='ready' AND senderId != deviceId AND (isBroadcast OR recipientIds contains deviceId)`, post-filtered in JS for exact CSV word match; `all` → ready files visible to the device (sent, broadcast, or recipient list contains deviceId). Ordered `createdAt desc`. Returns `{ files }`.
   122→6. `api/files/[id]/route.ts` — `GET`: returns FileRecord by id (404 if missing). `DELETE`: unlinks the stored file + any leftover `.partN` siblings, deletes the DB record, returns `{ ok: true }`.
   123→7. `api/download/[id]/route.ts` — `GET`: 404 if missing / not ready / file not on disk; increments `downloadCount`; streams `fs.createReadStream(storagePath)` wrapped in a Web `ReadableStream` whose `start/cancel` hooks wire Node stream events; returns `new Response(stream, { headers: Content-Type / Content-Disposition: attachment; filename="…" / Content-Length / Cache-Control: no-store })`.
   124→8. `api/messages/route.ts` — `POST { senderId, senderName, recipientId|null, content }`: upserts sender Device (and recipient Device if `recipientId` set, with placeholder name "Unknown Device"), creates Message, returns `{ message }`. `GET ?deviceId=&type=group|private&peerId=`: group → `recipientId IS NULL`; private → `(senderId=deviceId AND recipientId=peerId) OR (senderId=peerId AND recipientId=deviceId)`; both capped at the latest 200 messages and reversed to oldest-first ordering. Returns `{ messages }`.
   125→9. `api/devices/route.ts` — `GET`: returns all devices ordered `lastSeen desc` as `{ devices }`. `POST { id, name, deviceType, userAgent, avatarColor }`: `db.device.upsert` — on conflict updates name/deviceType/userAgent/avatarColor/lastSeen, on create uses provided values with sensible defaults (`deviceType='desktop'`, `avatarColor='#64748b'`). Returns `{ device }`.
